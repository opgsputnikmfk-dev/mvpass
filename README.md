# AI Crypto 3 — сигналы и понятное меню в Telegram

Один основной файл `bot.py`. Бот ищет LONG и SHORT по публичным свечам **Binance Spot** для ручной проверки фьючерсных идей. Он **не отправляет ордера**, не хранит ключи биржи и не обещает прибыль.

## Что изменилось

- Одна стратегия: **1 час — направление → 15 минут — откат → 5 минут — подтверждение**.
- До 25 монет из заданного набора криптоактивов: актуальная торговля, оборот от 10 млн USDT за сутки и спред до 10 базисных пунктов (0,1%). Если подходящих монет меньше, список короче. Стейблкоины и токенизированные акции не участвуют.
- Стоп за экстремумом отката с запасом 0,15 ATR на 15 минутах; одна цель вдвое дальше стопа. ATR здесь означает средний размер колебания цены. Издержки уменьшают фактическую прибыль относительно риска.
- Резкий запоздалый импульс, высокая доля расходов и известный разворотный уровень перед целью отменяют сигнал.
- Один откат — один назначенный вход, в том числе если вход позже отменился. Риск одной сделки до 0,25%, суммарно до 0,75%. Похожие движения делят лимит 0,35%; максимум 3 сделки, 2 в одном направлении. Объём модели ограничен без плеча.
- Сравнение с 15 похожими неперекрывающимися завершёнными сделками новой стратегии — только справка; оно никогда не блокирует сигнал. Пока истории мало, оценка не показывается.
- Компактный Telegram-дашборд: «Сделки», «Результаты», «Что ждём», «История», «Связь», «Как выбираем», «Риск», «Помощь». Кнопки редактируют одно сообщение. Вход, стоп и цель копируются отдельными кнопками.
- Статистика учитывает комиссию и ухудшение исполнения; выгрузка CSV, результаты по сторонам, монетам и дням. Статистика старой стратегии не подмешивается.

## Точные правила и ограничения

Часовой тренд: цена и EMA50 по одну сторону EMA200, наклон EMA50 за 3 свечи превышает 0,05 ATR по направлению. На 15 минутах ищется касание зоны EMA20–50 в последних 6 завершённых свечах после импульса не менее 0,8 ATR. Подтверждённый предыдущий разворот не должен быть сломан. Разворот требует двух закрытых свечей справа и слева. На 5 минутах нужна направленная свеча, закрывшаяся за максимумом/минимумом предыдущих трёх после закрытия свечи отката.

Временные ряды обрезаются по моменту решения **до расчёта индикаторов**. Незавершённые свечи и будущие подтверждения разворотов не используются. Вход назначается на следующую полную минуту после решения; модель обрабатывает его только после завершения этой минуты. Изменение цены более чем на 0,25 ATR 5m отменяет вход. На 1m-свече с одновременным касанием стопа и цели сначала считается стоп; разрыв цены исполняется по худшей цене открытия. Удержание ограничено 4 часами. После 3 убытков подряд — пауза 2 часа. Дневной лимит потерь 2%, лимит снижения от пика 8%.

Корреляция считается на закрытых часовых доходностях до момента решения, до 96 свечей; минимум 48 наблюдений. Совпадающий торговый риск при корреляции по направлениям ≥ 0,75 делит общий лимит. При нехватке данных однонаправленные сделки считаются связанными. Ожидающие входы резервируют риск и объём, чтобы несколько сигналов не заняли один бюджет.

Параметры — исходные исследовательские гипотезы, не результат оптимизации. Нет доказанной доходности, гарантированной частоты сделок или вероятности успеха. Спотовые уровни, стоимость удержания и фактическое исполнение отличаются от фьючерсов: **проверь выбранный контракт перед ручным входом**.

## Запуск и Render

Python закреплён в `.python-version`; зависимости в `requirements.txt`.

```sh
pip install -r requirements.txt
python -m unittest -v
python bot.py
```

На существующем Render-сервисе:

- Build Command: `pip install -r requirements.txt`
- Start Command: `python bot.py`
- `TELEGRAM_TOKEN` — существующая переменная окружения; токен в GitHub не добавлять.
- `ADMIN_CHAT_IDS` — через запятую; при отсутствии применяется ранее заданный владельцем ID `8299008675`.
- `SIGNAL_CHANNEL_ID` — необязательный существующий канал.
- `DATA_DIR` — папка SQLite. Для сохранения при замене сервера она должна находиться на постоянном диске.
- `INITIAL_EQUITY`, `RISK_PER_TRADE`, `FEE_BPS`, `SLIPPAGE_BPS` — необязательные параметры модели. По умолчанию 10000, 0.0025, 5.5, 2. Комиссия 0,055% за сторону — сценарий базового taker-тарифа Bybit без VIP, не подтверждённый тариф пользователя: https://www.bybit.com/en/help-center/article/Trading-Fee-Structure . Изменение учётных параметров требует нового `DATA_DIR`, чтобы результаты не смешивались.
- Старая переменная `MARKET` игнорируется: источник остаётся `data-api.binance.vision`, оба направления включены.
- На Render новый процесс ждёт 75 секунд перед запуском сканера и Telegram-поллинга, чтобы старый процесс завершился при развёртывании. Начальная загрузка свечей может занять ещё несколько минут. Локально задержки нет.

`GET /healthz` возвращает версию, свежесть рыночных данных, количество проверок и ошибки без токенов и личной статистики. `healthy` отражает работу цикла; `market_data_fresh` — наличие недавней оценки рынка. Если данных нет, свежесть будет `false`, даже когда процесс запущен.

**Существующий бесплатный Render — ограничение размещения:** он может засыпать без входящих запросов, а локальные файлы теряются при замене экземпляра. Этот код не покупает платный тариф и не обходит сон постоянными запросами к самому себе. Для круглосуточного сканирования и длительной истории нужен непрерывно работающий сервис с постоянным хранилищем. Сам код такого ограничения не устраняет.

Для открытия нового меню отправь `/start` или нажми старую кнопку «Обновить». Обычные переходы не добавляют сообщений; отдельные уведомления используются для новых сигналов/закрытий, явного сохранения карточки и CSV.

## Хранилище и тестирование

Новая база: `paper_pullback_v3.sqlite3`. При наличии старой базы копируются только ID панели, Telegram-offset и настройка включения. Старые файлы остаются неизменными; их незакрытые учебные позиции не продолжаются в новой стратегии. На временном диске Render старые файлы могут уже отсутствовать — код не может восстановить потерянную историю.

`test_bot.py` проверяет зеркальные LONG/SHORT, отсутствие будущих данных, подтверждение разворотов, стоп/цель, разрывы и расходы, сверку баланса, общий риск, повторные обновления, права доступа, копирование, одну панель и транзакции SQLite.

`backtest.py` воспроизводит те же `Runtime.monitor`, `Runtime.scan_one` и расчёт исполнения на исторических 1m-свечах. Telegram заменён локальной заглушкой. Никаких отправок сообщений и заявок. Исторический спред — явно заданное допущение, а не сегодняшняя котировка. Список монет фиксируется до проверки; сегодняшний рейтинг оборота не переносится в прошлое.

```sh
python backtest.py --symbols BTCUSDT ETHUSDT SOLUSDT --start 2026-10-24 --end 2026-10-31 --data-dir /tmp/replay --download --output validation.json
```

`validation.json`, если присутствует, содержит фактический результат короткой проверки, ограничения модели и причины пропусков. Это не полноценное исследование устойчивости: необходимы несколько независимых периодов, режимов рынка, проверка чувствительности к издержкам и наблюдение без изменения параметров по ходу.
