# Криптобот v2 — исправленная версия для проверки стратегии

Это Telegram-бот сигналов с **модельным счётом (paper trading)**. Как и присланный исходник, он не выставляет биржевые ордера. У него нет торговых API-ключей, плеча и интеграции с реальным счётом. Исправлены ошибки расчётов и контроля сделок; прибыльность новой стратегии **пока не установлена**.

**Начать с `AUDIT_RU.md`:** там разбор ваших 681 сделок, причины недостоверности прежнего отчёта, внесённые изменения и границы проверки.

## Что находится в архиве

| Файл | Назначение |
|---|---|
| `bot.py` | Готовый основной файл: KNN, модель исполнения, учёт капитала, Telegram-меню, HTTP health endpoint |
| `backtest.py` | Последовательная проверка одной пары/таймфрейма на минутных свечах |
| `download_data.py` | Загрузка публичных минутных свечей Binance и funding для USDM |
| `test_bot.py` | 31 автоматическая офлайн-проверка ошибок и граничных случаев |
| `requirements.txt` | Версии зависимостей, с которыми проведены проверки |
| `.env.example` | Пример переменных окружения; его нужно заполнить |
| `AUDIT_RU.md` | Анализ исходника и статистики |
| `VALIDATION.txt` | Фактический протокол проверок кода |

## Установка и запуск

Нужен Python **3.11 или новее**. Проверено на Python 3.12.14, NumPy 2.3.5, pandas 2.2.3. Запускайте из распакованной папки.

macOS / Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` текстовым редактором. Вставьте ваш Telegram-токен и числовой **user ID администратора**, а не имя пользователя. Пример `ADMIN_CHAT_IDS='123456789,987654321'`. Значение `SIGNAL_CHANNEL_ID` можно оставить пустым. Чтобы получать личные сообщения, сначала откройте бота в Telegram и нажмите «Старт». Для отправки в канал бот должен иметь соответствующее право.

Загрузите переменные и запустите:

```bash
set -a
source .env
set +a
python -m unittest -v test_bot
python bot.py
```

Файл `.env` **не читается автоматически**. На хостинге задайте те же значения в Environment Variables, установку — `pip install -r requirements.txt`, команду запуска — `python bot.py`. `PORT` берётся из окружения; по умолчанию 10000. Используется стандартный HTTP-сервер Python; Flask/Gunicorn для этой версии не нужны. Один процесс на один `DATA_DIR`. Первый запрос истории может занять несколько минут; health endpoint до первого успешного цикла вернёт 503.

Windows / PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:TELEGRAM_TOKEN = 'ВАШ_ТОКЕН'
$env:ADMIN_CHAT_IDS = 'ВАШ_ЧИСЛОВОЙ_USER_ID'
$env:MARKET = 'spot'
$env:DATA_DIR = 'data_v2'
.\.venv\Scripts\python.exe -m unittest -v test_bot
.\.venv\Scripts\python.exe bot.py
```

## Рынок, комиссии и параметры

Исходник брал spot-цены, хотя выдавал LONG и SHORT. В этой версии режим задаётся явно:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `MARKET` | `spot` | Только LONG по spot-данным. `usdm` — LONG/SHORT по данным USDT-фьючерсов, с funding в модельном счёте |
| `INITIAL_EQUITY` | `10000` | Условный начальный капитал, USDT |
| `RISK_PER_TRADE` | `0.0025` | 0,25% расчётного риска с издержками; это бюджет при обычном исполнении стопа, не гарантия максимального убытка |
| `FEE_BPS` | `10` | 0,10% за каждое исполнение: вход и каждый частичный выход |
| `SLIPPAGE_BPS` | `2` | 0,02% неблагоприятного сдвига цены на каждое исполнение |
| `DATA_DIR` | `data_v2` | Отдельная папка нового эксперимента |

Комиссии и проскальзывание — **допущения**, не найденные тарифы вашего аккаунта. Сверьте их со своими исполнениями. `10 bps` означает **0,10% на сторону**, а не 0,10% за весь круг. При одинаковой цене приблизительная сумма комиссий и проскальзывания по настройкам — 0,24% за круг. Частичное закрытие не удваивает объём комиссии: она начисляется на фактическое количество каждой части.

Остальные параметры находятся в `Config` в начале `bot.py`. По умолчанию:

- 15m, 1h, 4h; те же 10 монет, что в исходнике.
- ADX ≥ 20; направление подтверждается EMA200, EMA50 и наклоном EMA200. Вход на экстремальном RSI и после аномальной свечи/объёма отсекается.
- 15 ближайших исторических примеров с неперекрывающимися окнами результата; до 2500 свечей истории. Их средний результат ≥ 0,10 R и не менее 55% положительных результатов. Это пороги экспериментальной стратегии, **не доказанный оптимум и не вероятность успеха**.
- Стоп 1,5 ATR; TP1 на расстоянии 1 стопа закрывает 50%; TP2 на расстоянии 2 стопов закрывает остаток. Полный успех даёт **1,5 расстояния стопа** до издержек, а не 2. Денежный показатель `net_r` делит результат на риск с учётом издержек.
- После TP1 остаток получает стоп с компенсацией входной/выходной комиссии и заданного проскальзывания. Funding и гэпы эта формула не гарантирует покрыть.
- Таймаут 48 свечей исходного таймфрейма; на таймауте закрывается только остаток.
- Максимум 3 позиции всего, 2 одного направления, одна на монету во всех таймфреймах. Лимит расчётного риска 0,75%; позиции — до 25% капитала каждая; суммарный номинал — до 100%, без плеча.
- После 3 отрицательных результатов на таймфрейме — пауза на 24 его свечи. После убыточной сделки монета/таймфрейм получает 4 свечи паузы; после прибыльной — 1.
- Новые входы останавливаются при потере 2% относительно начала дня UTC или просадке 8% от максимума. Открытые позиции продолжают сопровождаться. Дневная пауза снимается на следующем дне UTC; пауза по общей просадке сохраняется после перезапуска.

Изменение параметров требует **нового `DATA_DIR`**: программа не смешивает разные эксперименты в одной статистике. После паузы по общей просадке сначала разберите журнал; не создавайте новый эксперимент только ради обхода ограничения.

## Что означает модельное исполнение

Сигнал вычисляется после закрытия свечи и только один раз на неё. Бот заранее назначает модельный вход на начало следующей полной минуты. Когда эта минута закроется, он использует её open с заданным проскальзыванием, затем проверяет диапазон. Поэтому сообщение о факте модельного входа может прийти примерно через минуту после назначенного времени, плюс задержки сети. Это **не приглашение считать историческую цену доступной для ручного входа**. Раннее сообщение о сигнале отдельно содержит ориентир и предупреждение, что вход может быть отменён.

При отклонении открытия более чем на 0,25 ATR от цены сигнала вход отменяется. Перед назначением проверяется текущий spread. Если SL и TP достигнуты внутри одной свечи, приоритет у уже действовавшего SL. Новый стоп после TP1 применяется только со следующей свечи. Все минутные свечи после входа обрабатываются по порядку; после простоя они догружаются. Отсутствующие свечи не заменяются выдуманными ценами. При недоступности данных сопровождения поиск новых сигналов приостанавливается.

Это приближение, а не биржевой движок: отсутствуют очередь заявок, точные сделки/тики, задержки исполнения, спецификации количества/минимальной стоимости, ликвидация и модель доступности заимствования. Режим spot поэтому не открывает SHORT. Режим USDM тоже остаётся модельным, с номиналом не выше капитала; он не моделирует реальную маржу.

Funding USDM начисляется по публичной истории, со знаком и оставшимся количеством. Если funding и выход находятся внутри одной минутной свечи, точный порядок по OHLC неизвестен: funding обрабатывается перед выходами этой свечи. Оценки капитала и просадки используются на закрытиях минут, а не на внутриминутных экстремумах. Лимиты останавливают **новые входы**, не являются гарантированным ограничением потерь.

## Проверка на исторических данных

Пример для 15m: запрашиваем 4 месяца минутных свечей, первые месяцы служат историей признаков/соседей, последние два — проверкой. Даты — **пример команды**, а не установленный период ваших скриншотов.

```bash
python download_data.py --symbol BTCUSDT --market spot --start 2026-06-01 --end 2026-10-01 --output market_data/BTCUSDT_spot_1m.csv
python backtest.py --csv market_data/BTCUSDT_spot_1m.csv --symbol BTCUSDT --market spot --tf 15m --start 2026-08-01 --output runs/BTC_15m_base
python backtest.py --csv market_data/BTCUSDT_spot_1m.csv --symbol BTCUSDT --market spot --tf 15m --start 2026-08-01 --slippage-bps 4 --output runs/BTC_15m_stress
```

Для 1h и особенно 4h нужна более длинная предыстория. Первые **1018 полных свечей** не используются для проверки; для полного рабочего окна желательно 2500 свечей. Пример: для 4h 2500 свечей — около 417 дней. Нельзя делать вывод о качестве свинга по нескольким десяткам сделок после короткого прогрева.

Для USDM используйте **USDM-свечи** и соответствующий funding:

```bash
python download_data.py --symbol BTCUSDT --market usdm --start 2026-06-01 --end 2026-10-01 --output market_data/BTCUSDT_usdm_1m.csv
python backtest.py --csv market_data/BTCUSDT_usdm_1m.csv --symbol BTCUSDT --market usdm --tf 15m --start 2026-08-01 --funding market_data/BTCUSDT_usdm_1m.csv.funding.json --output runs/BTC_usdm_15m
```

Бэктест работает на будущих относительно обучающих примеров данных, с последовательным добавлением уже известных исходов. Сосед допускается только когда весь его 48-свечный результат **завершился до свечи сигнала**. Признаки и нормализация не используют будущие строки. Перебора «самых прибыльных» параметров по всему периоду здесь нет.

Результаты: `summary.json`, полный `trades.json`, кривая капитала `equity.csv`. Есть profit factor, net PnL, средний R, просадка по наблюдавшимся отметкам, издержки и результаты трёх последовательных частей периода. Позиция в конце выборки принудительно закрывается с издержками и меткой `END_OF_DATA`, чтобы не скрыть открытый убыток.

**Ограничения бэктеста:** одна пара и один таймфрейм за запуск; их доходности нельзя складывать как доходность общего портфеля. Исторические KNN-метки оцениваются на свечах исходного таймфрейма, поэтому разрешение хуже, чем минутное сопровождение; правила выходов общие. Funding учтён в replay USDM, но **не включён в KNN-метки**. Исторического стакана/spread нет, поэтому live-фильтр spread в бэктесте не воспроизводится. По умолчанию моделируется задержка входа 1 минута; можно отдельно проверить `--entry-delay-minutes 2`. Эти отличия требуют последующей paper-проверки.

При собственном CSV нужны колонки `ts,open,high,low,close,volume,close_ts`; время — целые миллисекунды UTC, ровные минуты без пропусков и дублей. Рядом нужен файл `имя.csv.meta.json` с подтверждёнными `market` и `symbol`. Funding для USDM требует JSON-объект `market,symbol,start_ms,end_ms,events`; каждая запись events содержит `fundingTime,fundingRate,markPrice`. Метаданные помогают выявить подмену рынка/периода, но не доказывают подлинность чужого CSV.

## Переход со старой версии

1. Сохраните копию старого проекта и JSON-файлов статистики/позиций. Не запускайте старую и новую версии одновременно с одним Telegram-токеном: два `getUpdates`-процесса конфликтуют.
2. Старые активные сигналы необходимо отдельно сверить и завершить по прежним правилам. **Они не импортируются автоматически**, потому что новые выходы и размеры позиций несовместимы со старыми. Если по старым сигналам открыты реальные сделки, новая программа их не увидит.
3. Используйте новую папку `data_v2`; старые JSON-файлы эта версия не читает и не удаляет. ADX 30–39 из старой памяти в новый эксперимент не переносится.
4. Сначала проверьте работу на модельном счёте и сравните будущий независимый период. Проведённые 31 тест не подтверждают торговую доходность.

Вся история теперь находится в `data_v2/paper.sqlite3`. Не оставляйте эту папку на временном диске хостинга; обеспечьте постоянный том и резервную копию. При резервировании работающего SQLite используйте SQLite backup API; обычное копирование одного `.sqlite3` без WAL может быть неполным. Простой вариант — остановить бот и скопировать всю папку.

Офлайн-отчёт и выгрузка:

```bash
python bot.py --report
python bot.py --export closed_trades.json
```

После аварийного завершения может остаться `running.lock`. Удаляйте его только убедившись, что прежний процесс действительно остановлен. Параметры конфигурации и состояние лимитов сохраняются в базе. Telegram-токен и числовые ID не включены в готовый код.
