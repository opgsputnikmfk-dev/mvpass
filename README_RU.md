# AI Crypto Analyst 4.0

Новый самостоятельный проект: анализ фьючерсов, переключаемые фильтры,
учебные сделки, Telegram и веб-дашборд. Старый `bot.py` для запуска не нужен.
Распакуйте **всю папку**: новый `bot.py` — точка входа, модули лежат в `analyst/`.

**Статус:** рабочая исследовательская версия. Реальных ордеров в коде нет.
Доходность стратегии не подтверждена. Тесты проверяют поведение программы.
Демонстрационные свечи искусственные и всегда отмечены `SYNTHETIC_DEMO`.

## Быстрый запуск на Windows

1. Установите Python **3.11 или новее**, если его ещё нет.
2. Распакуйте архив в отдельную папку.
3. Запустите `start_demo.bat`. Он создаст виртуальное окружение, установит три
   зависимости и подготовит демонстрацию. При первом запуске потребуется немного времени.
4. После сообщения о запуске откройте **http://127.0.0.1:8765**.

Демо работает без Telegram, биржевых ключей и доступа к бирже.
В нём можно посмотреть сигналы, графики, результаты и переключатели.
Переключение в демо создаёт пустую новую серию: исторические результаты
не пересчитываются автоматически при клике. Для нового расчёта используйте `backtest`.

Для наблюдения за настоящим рынком запустите `start_paper.bat`.
Это также учебные сделки, но по публичным данным Bybit.
Доступность Bybit зависит от вашей среды и региона; программа не обходит ограничения.
При недоступности данных дашборд показывает `DATA_ERROR`, без подмены фьючерсов спотом.

## Запуск вручную: Windows / macOS / Linux

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate
python -m pip install -r requirements.txt
python bot.py demo
```

Запускайте только соответствующую вашей системе команду активации.

```bash
python bot.py doctor
python bot.py serve
python bot.py serve --config configs/default.json
python -m unittest discover -s tests -v
```

`--config` используется при **первом** создании базы. Затем актуальные настройки
загружаются из SQLite и меняются в дашборде. Для полностью отдельного запуска:
`python bot.py serve --data-dir .data-second --config configs/default.json`.

## Telegram

Скопируйте `.env.example` в `.env` в корне проекта и заполните:

```dotenv
TELEGRAM_BOT_TOKEN=токен_вашего_бота
TELEGRAM_CHAT_ID=числовой_id_вашего_личного_чата
```

Токен создаётся через BotFather. `TELEGRAM_CHAT_ID` — ID вашего пользователя,
не username и не ID группы. Его можно получить из поля `message.chat.id`
ответа Bot API `getUpdates` после сообщения боту. Не публикуйте URL с токеном.
Здесь намеренно требуется личный чат с положительным ID.

```bash
python bot.py serve --telegram
```

Отправьте боту `/start`. Управление разрешено только указанному владельцу.
Не запускайте одновременно старый и новый процесс с одним Telegram-токеном:
они будут конкурировать за `getUpdates`. Код сам не выключает старые сервисы.

Команды:

| Команда | Действие |
|---|---|
| `/start`, `/menu`, `/filters` | Дашборд и пять страниц переключателей |
| `/filter fibonacci on` | Включить фильтр Фибоначчи |
| `/filter rsi observe` | Наблюдать RSI без блокировки входа |
| `/filter ema off` | Выключить участие EMA в отборе |
| `/setups` | Список сценариев |
| `/setup breakout on` | Включить пробой |
| `/pause`, `/resume` | Пауза / возобновление новых входов |
| `/stats` | Сравнение учебных счетов |
| `/chart BTCUSDT` | График и уровни последнего сценария |

Пауза отменяет ещё не исполненные сигналы. Открытые учебные позиции продолжают
сопровождаться по своим правилам. Сценарий и подтверждённый учебный вход —
разные уведомления. Вход/стоп/цель копируются кнопками в карточке сценария.

## Что реализовано

- Bybit **USDT linear perpetual**. По умолчанию BTCUSDT, ETHUSDT, SOLUSDT.
- Четыре сценария: откат по тренду, пробой канала, ложный пробой, возврат в диапазон.
- Закрытые свечи 5м / 15м / 1ч / 4ч. В этой версии таймфреймы фиксированы в коде.
- Подтверждённые экстремумы, поддержка/сопротивление и разметка Фибоначчи.
- 25 фильтров с режимами `on`, `observe`, `off` и общими числовыми настройками.
- Причины допуска/отказа, запись всех найденных кандидатов, в том числе отклонённых.
- Учебный портфель с комиссиями, проскальзыванием, funding, задержкой входа,
  лимитами риска и времени, опциональным трейлингом.
- Три параллельных счёта: активные настройки, базовые сценарии без фильтров,
  сочетание EMA + ATR + Фибоначчи + пространство до уровня.
- Версии настроек и отдельные серии; старые позиции сохраняют правила выхода.
- SQLite с транзакциями, восстановление состояния и очередь уведомлений.
- Адаптивный дашборд, графики свечей, разбор проверок, CSV с понятными датами.
- Лаборатория: **28 вариантов** — базовый, каждый из 25 фильтров отдельно,
  выбранная конфигурация и сочетание EMA/ATR/объём/уровни.
- Протокол разделения истории, защита от повторного использования контрольного
  периода как «нового», стресс-тест расходов выбранного варианта.

В `docs/FILTERS_RU.md` описана точная логика каждого фильтра.
Переключатель `off` исключает фильтр из решения; его признаки всё равно могут
рассчитываться и сохраняться для общего аудита и сравнения.

## Как работает решение

1. Загружаются непрерывные минутные свечи, агрегируются полные старшие свечи.
2. Анализируются тренд и экстремумы, формируются сценарии с подтверждением.
3. Для каждого сценария рассчитываются 25 проверок, стоп и предварительная цель.
4. Если сценарий и включённые фильтры разрешают вход, он попадает в очередь.
5. Вход моделируется на открытии будущей минутной свечи, минимум через минуту
   после принятия решения. В реальном наблюдении дополнительно округляется время
   до следующей минуты. Поэтому задержка может быть больше одной минуты.
6. Перед входом заново проверяются доступный риск, смещение цены, размер стопа,
   спецификация контракта и пространство до цели. При отказе причина записывается.
7. Позиция закрывается по стопу, цели или времени. Трейлинг, если включён,
   начинает действовать только со следующей минуты после изменения стопа.

Это последовательность правил, а не вызов LLM для каждой свечи. Внешняя LLM,
автоматический новостной анализ и платные данные в эту версию не подключены.
Текст объяснения строится из фактических расчётов; отдельных расходов на LLM нет.

Если нет данных для включённого фильтра, он блокирует сигнал. `observe` при
отсутствии данных показывает «нет данных» и не влияет на допуск.
При выключенных сценариях сигналов нет, независимо от фильтров.

## Параметры риска

Все числа — исходные **допущения для исследования**, а не подобранная прибыльная стратегия.

| Параметр | По умолчанию |
|---|---:|
| Учебный капитал | 10 000 USDT |
| Риск сделки с расчётными комиссиями и проскальзыванием | 0,25% |
| Общий открытый запланированный риск | до 0,75% |
| Риск позиций одного направления | до 0,50% |
| Открытых позиций | до 3, одна на монету |
| Общая номинальная экспозиция | не более 1× капитала |
| Пауза новых входов после дневного убытка | 2% |
| Постоянная остановка новых входов серии при просадке | 8% |
| Цель | 2 расстояния до первоначального стопа |
| Максимальное удержание | 240 минут |
| Комиссия за сторону | 0,055%, изменяется в настройках |
| Проскальзывание за сторону | 3 базисных пункта, изменяется |
| Трейлинг | выключен (`trailing_atr = 0`) |

Плечо биржи и ликвидации не моделируются: экспозиция ограничена 1× капитала.
Стоп не гарантирует точного ограничения потерь при разрыве цены. Ограничение
одной стороны — грубая защита концентрации, не полноценная корреляционная модель.
Дневные границы и графики используют UTC. Защитные остановки ограничивают новые
входы; уже открытые позиции выходят по исходным правилам.

При сохранении настроек создаётся новая серия с новым учебным капиталом.
Возврат к прежним настройкам тоже создаёт новую серию. Суммировать результаты
этих счетов как доходность одного реального счёта нельзя.

## Исторические данные и backtest

Загрузка публичной минутной истории и funding, конец периода исключается:

```bash
python bot.py download --out datasets/bybit --start 2025-01-01 --end 2026-01-01 --symbols BTCUSDT,ETHUSDT,SOLUSDT
```

Большой период требует многих запросов и места. Сначала проверьте `doctor`.
BTC дополнительно загружается для контекстного фильтра. Архивы не включены в код.

```bash
python bot.py backtest --data datasets/bybit --config configs/research3.json --start 2025-02-01 --end 2025-04-01 --out reports/manual --all-filters
```

В начале данных нужно минимум 210 полных часовых свечей для прогрева.
Рекомендуем выделять 14 дней и более. Любой просмотренный период из ручного
`backtest` впоследствии нельзя честно назвать новым независимым тестом.

Результаты: `report.json`, `comparison.csv`, сделки и капитал каждого варианта,
`candidates.jsonl` со всеми ситуациями и `equity.png`. Число допущенных кандидатов
не равно числу исполненных сделок: вход может отмениться из-за цены или риска.

Формат свечей: `ts,open,high,low,close,volume`. `ts` — время **открытия** минутной
свечи в миллисекундах UTC. Нельзя подставлять спотовые данные под имя фьючерса.
В `manifest.json` фиксируются источник, границы, спецификации и SHA-256 файлов.
Пропуски, повторные минуты, неверные OHLC и контрольные суммы останавливают расчёт.

Данные стакана, спреда, ожидаемого funding и OI задним числом не выдумываются.
Без архивных снимков соответствующие варианты будут отмечены
`UNAVAILABLE_FEATURES`. Исторические **выплаты** funding всё равно учитываются
отдельно от фильтра ожидаемого funding перед входом.

При наличии архивных снимков добавьте в manifest:

```json
"snapshot_files": {"BTCUSDT": "BTCUSDT_snapshots.json"}
```

И SHA-256 этого файла в `files`. Внутри — массив объектов:

```json
[{"ts": 1735689600000, "spread_bps": 2.0, "depth_usdt": 1000000,
  "funding_rate": 0.0001, "oi_change_pct": 0.2}]
```

`ts` — когда снимок стал **доступен**, не время события, опубликованного позже.
Снимок старше 120 секунд считается недоступным; будущие снимки не используются.
В режиме наблюдения такие снимки автоматически сохраняются в SQLite.

## Зафиксированное исследование

```bash
python bot.py lab-init --data datasets/bybit --config configs/research3.json --out reports/experiment-01
python bot.py lab-run --data datasets/bybit --out reports/experiment-01 --stage develop
python bot.py lab-run --data datasets/bybit --out reports/experiment-01 --stage select
python bot.py lab-run --data datasets/bybit --out reports/experiment-01 --stage holdout
```

Первые 14 дней — прогрев, оставшаяся история делится по времени: 50% разработка,
25% отбор, 25% контроль. Параметры и границы замораживаются в протоколе.
Этап не запускается дважды в том же эксперименте. Даже прерванный запуск
помечается как открытие периода. Для повторного исследования нужно явно
зафиксировать новый эксперимент и раскрыть, какие даты уже просматривались.

Порог допуска к контрольному периоду: минимум 30 сделок на отборе, profit factor
≥1,2, положительный средний R, просадка ≤8%, отсутствие недоступных активных
признаков. Среди прошедших выбирается максимальный средний R; правило фиксируется
до расчёта. В holdout одновременно считается стресс: комиссия ×1,5,
проскальзывание ×2. Если никто не прошёл, контрольный период не открывается.

Эти пороги только отбирают кандидата для дальнейшего исследования. Они не
сертифицируют стратегию. Бот автоматически не заменяет действующие настройки
«победителем». Необходимы другие периоды, проверка соседних параметров и
наблюдение на новых сигналах. Соседние параметры проверяются отдельными заранее
описанными `backtest`-запусками; автоматический перебор миллионов сочетаний отсутствует.

Для среднего R есть описательный bootstrap по дням (если дней с входами ≥5).
Он не исправляет множественный перебор и зависимость длинных сделок между днями.
Атрибуция фильтров группирует только **исполненные** базовые сделки и не является
причинной оценкой. Для портфельного сравнения используйте отдельные варианты.

## Сервер и хранение

`serve` запускает сканер и HTTP-сервер в одном процессе. SQLite находится в
`DATA_DIR` (`.data` по умолчанию). Демо и рыночное наблюдение используют разные базы.
Для работы 24/7 нужны постоянно работающий процесс и постоянный диск.
Скопируйте базу вместе с WAL-файлами после остановки процесса либо используйте
штатный SQLite backup API; копирование только `.sqlite` при работающем WAL небезопасно.

По умолчанию интерфейс доступен только на этом компьютере. Для внешнего доступа:

```dotenv
DASHBOARD_PASSWORD=случайный_пароль_не_короче_16_символов
PUBLIC_ORIGIN=https://ваш-домен.example
```

```bash
python bot.py serve --host 0.0.0.0 --telegram
```

Поставьте HTTPS reverse proxy, передающий исходный `Host`. Встроенный сервер
предназначен для личного использования, не для открытого многопользовательского
сервиса. Без пароля внешнее прослушивание запрещено. Доступ защищён сессией,
проверкой Origin/Host и CSRF-заголовком. Telegram проверяет ID владельца.

`Dockerfile` включён для самостоятельного размещения: смонтируйте `/data` и
передайте переменные окружения. По умолчанию контейнер запускает Telegram,
поэтому нужны обе его переменные; команду можно переопределить для веб-режима.
Файл `.env` исключён из Git и контекста Docker. Биржевые ключи не требуются.

## Ограничения, которые важно учитывать

- Версия исследовательская; реальные биржевые ордера и LLM-анализ не реализованы.
- Прямой доступ к Bybit из среды разработки 04.11.2026 вернул HTML недоступности.
  Разбор API проверен тестами; полный цикл на реальной бирже здесь не подтверждён.
- Визуальные школы вроде SMC/ICT сведены к конкретным формулам. Это не полная
  реализация этих школ. Волны Эллиотта, все виды треугольников/флагов, footprint,
  CVD по тикам, новости и on-chain потоки не реализованы.
- Профиль объёма приближён по OHLCV, без распределения реальных тиков по цене.
- Funding: историческая ставка × цена открытия минутной mark-свечи. Цена
  на точную миллисекунду выплаты неизвестна: это явно отмеченное приближение.
- Загрузчик запрашивает историю выплат, но не доказывает полноту всех старых
  расписаний funding. Проверка полноты минутных свечей строже этой проверки.
- Спецификации контракта для исторического теста берутся текущие. Изменения
  шагов цены/объёма в прошлом не восстановлены.
- Стоп/цель проверяются по минутным high/low. Если оба достигнуты, первым
  считается стоп. Точный порядок внутри минуты неизвестен.
- Просадка считается по минутным ценам, не по каждому тику. Экстремальная
  внутриминутная просадка может быть больше.
- Проскальзывание фиксированное, очередь заявок и собственное влияние на рынок
  не моделируются. Отчёт отражает модель, не обещание такого исполнения.
- Вживую вход назначается после времени фактического анализа, в backtest —
  после закрытия свечи плюс задержка. Сетевая задержка может ухудшить соответствие.
- Риск-блок оценивает ликвидность на момент сигнала; архивная минутная модель
  не знает стакан на будущий момент исполнения.
- Уведомления доставляются из очереди с повторением при ошибке. После аварии
  возможен повтор сообщения; ID сценария помогает его распознать.
- История не обрезается автоматически. Следите за объёмом диска и числом серий.

## Дашборд 4.1

Главная показывает состояние подключения, все выбранные монеты и время фактического анализа.
В разделе «Фильтры и их результаты» все переключатели собраны в одну таблицу.
Отдельный раздел «Статистика наборов» сравнивает реально наблюдаемые сочетания:
«Мои фильтры», «Без дополнительных фильтров», «Тренд + Фибоначчи».
Каждый набор показывает точный состав, допуски, закрытые сделки, результат,
долю удачных сделок, просадку, разбивку по монетам/сценариям и экспорт сделок.
Архивные серии доступны в списке; сравнивать разные даты как равные эксперименты нельзя.
Результаты отдельных фильтров — группировка базовых сделок, а статистика сочетаний —
результаты отдельных учебных счетов. Все возможные сочетания автоматически не перебираются.
В Telegram: /start — главная, /coins — монеты, /combinations — сочетания, /filters — режимы.


## Список монет 4.2

В рыночном `serve` без явного `--config` включён автоматический топ-20
криптофьючерсов Bybit USDT perpetual по `turnover24h`, с обновлением раз в сутки.
Учитываются только активные контракты с историей не короче окна прогрева.
Исключаются стейблкоины, предварительные листинги и известные типы TradFi.
Неизвестные типы продуктов не включаются автоматически.
Если рейтинг недоступен, используются 20 сохранённых/резервных монет и явно
показывается, что актуальный топ не подтверждён. Повтор рейтинга — через час.
Изменение состава создаёт новую серию статистики; рейтинг не применяется, если
он исключит монету с открытой позицией или ожидающим входом. Добавление монет
допускается без принудительного закрытия старых позиций. Фильтры и риск сохраняются.
Резерв: BTC, ETH, SOL, BNB, XRP, DOGE, ADA, AVAX, LINK, DOT, SUI, NEAR, LTC, BCH,
UNI, AAVE, ATOM, FIL, ARB, OP. Это резерв, а не подтверждённый текущий рейтинг.
Автовыбор используется только в реальном наблюдении, не в историческом тесте.
Для демо и проверки на трёх монетах есть `configs/research3.json`; в демо без
конфига используются BTC/ETH/SOL из искусственного датасета.
Явный `serve --config ...` использует заданный список без автоматического рейтинга.
Реальные ордера по-прежнему отсутствуют.
